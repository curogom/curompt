# Public 저장소용 라이선스 옵션 (MIT 대안)

## MIT보다 제한적인 라이선스 옵션

### 1. Apache 2.0 (추천)
**제한 수준**: ⭐⭐⭐ (MIT보다 약간 제한적)

**특징:**
- MIT + 특허 보호 추가
- 상업적 사용 허용
- 수정/배포 자유
- **차이점**: 특허권 포기, 변경 사항 명시 요구

**장점:**
- 기업 친화적이면서도 오픈소스
- 특허 소송 방어
- MIT보다 약간 더 제한적

**단점:**
- MIT보다 약간 복잡한 라이선스

---

### 2. MPL 2.0 (Mozilla Public License)
**제한 수준**: ⭐⭐⭐⭐ (상당히 제한적)

**특징:**
- **파일 단위 copyleft**: 수정한 파일만 소스 공개 의무
- 상업적 사용 허용
- 다른 라이선스와 병합 가능

**장점:**
- 오픈소스이지만 수정 사항 공개 범위가 제한적
- 파일 단위로만 제한되어 실용적

**단점:**
- 상대적으로 덜 알려진 라이선스

---

### 3. BSL 1.1 (Business Source License)
**제한 수준**: ⭐⭐⭐⭐⭐ (가장 제한적이면서도 오픈소스)

**특징:**
- **일정 기간 후 오픈소스 전환** (예: 4년)
- 초기에는 상업적 사용 제한
- 소스 코드는 공개 (Public 저장소 가능)
- 특정 용도 제한 가능

**예시:**
```bsl
Additional Use Grant: You may not use the software provided under this license 
to compete with CuroGom's commercial offerings.

Conversion Date: January 1, 2029 (4 years from now)
```

**장점:**
- Public 저장소 가능
- 일정 기간 상업적 보호
- 명확한 전환 시점

**단점:**
- 라이선스가 복잡함
- GitHub에서 자동 인식 안 될 수 있음

---

### 4. AGPL-3.0 (Affero GPL)
**제한 수준**: ⭐⭐⭐⭐⭐ (매우 제한적)

**특징:**
- **강한 copyleft**: 서비스 제공 시에도 소스 공개 의무
- 수정본도 같은 라이선스
- 상업적 사용은 가능하나 소스 공개 필수

**장점:**
- 가장 강한 오픈소스 정신
- 서비스 제공 시에도 소스 공개 보장

**단점:**
- 상업적 활용에 부담
- 기업들이 피하는 경향

---

### 5. 커스텀 라이선스 (제한적 오픈소스)
**제한 수준**: ⭐⭐⭐⭐⭐ (가장 유연함)

**예시:**
```
소스 코드는 공개되지만:
- 개인/교육 목적으로만 사용 가능
- 상업적 사용은 별도 허가 필요
- 수정본 공개 의무 (또는 의무 없음)
```

**장점:**
- 완전한 제어권
- 목적에 맞게 설정

**단점:**
- GitHub에서 "Other"로 표시
- 법적 검토 필요
- 기여자들이 이해하기 어려울 수 있음

---

## 추천 순위 (Public + 제한적)

### 1순위: Apache 2.0 ⭐⭐⭐
- MIT보다 약간 제한적이면서도 널리 인정받음
- 기업 친화적
- Public 저장소에 적합

### 2순위: MPL 2.0 ⭐⭐⭐⭐
- 파일 단위 제한으로 실용적
- Public이면서도 수정 사항 공개 범위 제한

### 3순위: BSL 1.1 ⭐⭐⭐⭐⭐
- 일정 기간 후 완전 오픈소스
- 상업적 보호 가능

## 비교표

| 라이선스 | 상업적 사용 | 수정 허용 | 소스 공개 의무 | 제한 수준 |
|---------|-----------|---------|--------------|----------|
| MIT | ✅ 자유 | ✅ 자유 | ❌ 없음 | ⭐⭐ |
| Apache 2.0 | ✅ 자유 | ✅ 자유 | ❌ 없음 (변경 명시) | ⭐⭐⭐ |
| MPL 2.0 | ✅ 자유 | ⚠️ 파일별 | ⚠️ 수정 파일만 | ⭐⭐⭐⭐ |
| BSL 1.1 | ⚠️ 제한적 | ✅ 자유 | ✅ 있음 | ⭐⭐⭐⭐⭐ |
| AGPL-3.0 | ✅ 가능 | ⚠️ 필수 | ✅ 모든 경우 | ⭐⭐⭐⭐⭐ |

## 결론 및 추천

**Public 저장소이면서도 MIT보다 제한적인 옵션:**

1. **Apache 2.0** (가장 추천)
   - MIT의 모든 권리 + 특허 보호
   - 널리 인정받음
   - 기업도 사용하기 편함

2. **MPL 2.0** (파일 단위 제한 원할 때)
   - 수정한 파일만 공개
   - 실용적

3. **BSL 1.1** (상업적 보호 필요할 때)
   - 일정 기간 상업적 제한 가능
   - 나중에 MIT/Apache로 전환
