# Roadmap

> 상세한 개발 계획과 기간 추정은 프로젝트 내부 문서를 참조하세요.

## 개발 전략

단계별 개발을 통해 핵심 기능부터 점진적으로 확장합니다. 각 마일스톤은 독립적으로 배포 가능한 단위입니다.

## M1: MVP (핵심 기능) - 약 5-8주

**목표**: 기본적인 프롬프트 분석 및 평가 도구 완성

### 핵심 기능
- ✅ `scan`, `eval`, `suggest` 기본 CLI 커맨드
- ✅ 프롬프트 정적 분석
  - Markdown 섹션 구조 분석 (ROLE, INPUTS, OUTPUT FORMAT 등)
  - 중복 규칙 감지
  - 토큰 계산 (Claude, OpenAI)
- ✅ 점수화 엔진 (0-100 종합 점수)
  - structure, conciseness, instruction_following, risk 메트릭
- ✅ Markdown 리포트 생성
- ✅ Redaction (비밀값 마스킹)
- ✅ Provider 어댑터 (Claude 우선, OpenAI 추가)
- ✅ 기본 리팩터 제안 (중복 제거, 토큰 절감)
- ✅ SQLite 저장소

**산출물**: 사용 가능한 CLI 도구, 기본 문서

---

## M2: 동적 평가 - 약 3-4주 (M1 완성 후)

**목표**: 실제 LLM 호출을 통한 프롬프트 성능 평가

### 추가 기능
- ✅ 다중 샘플 생성 (temperature grid 지원)
- ✅ 자체 일관성 검증 (샘플 간 키/포맷 일치율)
- ✅ JSON Schema 검증
- ✅ 비용 및 지연 시간 추적
  - 토큰 사용량
  - p50/p95 지연 시간
  - 비용 계산
- ✅ JSON 리포트 형식

**고려사항**: API 비용 발생, 필요성 검토 후 구현 권장

---

## M3: 리팩터 자동 적용 - 약 3-5주

**목표**: 프롬프트 최적화 제안의 자동 적용

### 추가 기능
- ✅ 프롬프트 구조 깊이 분석
- ✅ Few-shot 예제 축약 알고리즘
  - 예제 중요도 평가
  - 최소 예제 선택
- ✅ 캐시 최적화 가이드
- ✅ 자동 적용 엔진
  - 백업 및 롤백 기능
  - 적용 전후 비교 리포트

**고려사항**: 알고리즘 연구 필요, 기본 제안만 먼저 구현

---

## M4: 팀 프리미엄 - 약 3-5주 (선택 사항)

**목표**: 팀 단위 사용을 위한 고급 기능

### 추가 기능
- ✅ 집계 대시보드
  - 팀 전체 프롬프트 통계
  - 트렌드 분석
- ✅ 규정 집행
  - 프롬프트 정책 검증
  - 자동 리젝션 규칙
- ✅ 사내 프록시 배포
  - 중앙화된 모니터링
  - 사용량 제한

## 우선순위

### 필수 (M1)
1. 정적 분석 (구조, 토큰, 규칙)
2. 점수화 엔진
3. 기본 리포트 (Markdown)
4. Redaction (보안)
5. Provider 지원 (Claude 1개 우선)

### 높은 우선순위
1. 리팩터 제안 (기본)
2. SQLite 저장소

### 선택 사항
1. 동적 평가 (M2) - 비용 및 복잡도 고려
2. 자동 리팩터 (M3) - 알고리즘 연구 필요
3. 팀 기능 (M4) - 수요 확인 후

## 리스크 관리

- **동적 평가 복잡도**: M1 완성 후 필요성 재평가 권장
- **Provider API 변경**: 어댑터 패턴으로 추상화
- **알고리즘 연구**: 기본 구현 우선, 고도화는 후속

## 다음 단계

1. **Week 1-2**: 프로젝트 구조 및 기본 CLI 구현
2. **핵심 기능 우선**: 정적 분석 → 점수화 → 리포트
3. **Provider는 1개만**: Claude 우선 (API 안정성)
4. **동적 평가는 보류**: M1 완성 후 필요성 재평가
